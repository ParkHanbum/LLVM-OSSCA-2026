#152948 이슈 분석

https://github.com/llvm/llvm-project/issues/152948

이슈 해석

Missed fold:  x == c || (c + 1 <= x && x <= c2)  =>  (c <= x
&& x <= c2) #152948

C example

#include <stdint.h>
using u32 = uint32_t;
auto inline in_range(auto x, auto lo, auto hi) -> bool {
    return lo <= x && x <= hi;
}

-> 보조함수로 값 x가 lo 이상이고 hi 이하인지 검사한다.

extern "C" { // 0x7f = 127, 0x80 = 128, 0x9f = 159
auto src(u32 c) -> bool { return (c == 0x7f) || in_range(c,
0x80, 0x9f); }
// src -> c == 127 || (128 <= c && c <= 159);
auto tgt(u32 c) -> bool { return in_range(c, 0x7f, 0x9f); }
// tgt -> 127 <= c && c <= 159;
}
// => 따라서 src / tgt 둘다 참을 반환하는 값(127~159)은 완전히 같

다.

assembly

src: ; 보통함수의 첫번째 정수 인수가 w0에 들어옴 -> w0 = c
    mov     w8, #128
  ; 레지스터 w8에 128을 넣는다.

(x == A) || ((x & -Pow2) == A + 1)   → 이것을 하나의 연속 범위 검사로 바꾸는 것이다.
x == 127 || (x & -32) == 128

→

 %offset = add i32 %x, -127
%cmp = icmp ult i32 %offset, 33

이와같이 폴드 한다.

테스트는 두 가지로 나뉘는데

positive test: 반드시 최적화되어야 하는 경우

negative test: 절대로 잘못 최적화하면 안 되는 경우

이다.

Positive Test

최적화가 가능한 패턴을 실제로 하나의 범위 검사로 변환하는지 확인한다.

1. 기본 OR + EQ 패턴

x == 127 || (x & -32) == 128
결과:
127 <= x <= 159

%ret = icmp ult i32 %offset, 33

3. AND + NE 패턴

x != 127 && (x & -32) != 128

이는 기본 OR 조건의 부정 형태이다.

x가 127~159 범위 밖에 있음

EQ + OR뿐 아니라 대응되는 NE + AND도 범위 검사로 변환하는지 확인한다.

4. 피연산자 순서 변경

(x & -32) == 128 || x == 127

조건의 순서가 반대여도 동일하게 최적화되는지 확인한다.

AND + NE의 순서가 반대인 경우도 함께 테스트한다.

Negative Test

조건을 만족하지 않는 패턴을 잘못 범위 검사로 변환하지 않는지 확인한다.

1. and 결과가 여러 곳에서 사용되는 경우

2. 잘못된 AND + EQ 조합

x == 127 && (x & -32) == 128

두 조건은 동시에 참일 수 없으므로 결과는 항상 false이다.

새로운 range fold가 아니라 기존 InstCombine의 상수화가 적용되는지 확인한다.

3. 마스크가 power-of-two 형태가 아닌 경우

(x & -33) == 128

33 은 32 , 64 와 같은 negative power-of-two mask가 아니다.

연속된 범위를 나타낸다고 보장할 수 없으므로 fold하지 않는다.

4. 비교 상수가 마스크와 정렬되지 않은 경우

(x & -32) == 16

x & -32의 결과는 32의 배수이므로 16이 될 수 없다.

잘못된 범위로 해석하지 않고, 기존 단순화만 수행하는지 확인한다.

5. 범위가 서로 인접하지 않은 경우

x == 126 || (x & -32) == 128

두 번째 조건은 128~159를 의미하지만 127이 빠져 있다.

문제와 목표

CPP
// Before
return c == 127 || (128 <= c && c <= 159);
// After
return 127 <= c && c <= 159;

두 식은 같은 정수 집합을 나타낸다. 부호 없는 값에서는 하한을 뺀 뒤 범위의 길이와 비교하는 형태로도 정규화할 수 있다.

IR과 기계어의 차이

자료는 첫 식의 여러 비교·비트 연산과 두 번째 식의 단순한 범위 비교를 대조한다. foldAndOrOfICmpsUsingRanges의 기존 범위 처리를 추적한다.

수학적으로 붙어 있는 구간이라는 사실과, 정해진 비트 폭에서 넘침까지 포함해 올바른 IR 변환이라는 사실을 함께 확인해야 한다.

적용하면 안 되는 경우

  • 두 구간 사이에 빈 값이 있으면 하나의 연속 범위로 합치지 않는다.
  • 부호 있는 비교와 부호 없는 비교를 구분한다.
  • 마스크 결과가 다른 곳에서도 사용되는지 확인한다.
  • 경계값을 더하거나 뺄 때 정수 넘침 조건을 확인한다.

원자료에는 하나의 연속 범위가 아닌 사례와 masked compare의 추가 사용처를 포함한 negative 테스트가 있다.

검증과 효과 해석

작성자는 최소 IR, 기계어, llvm-mca와 벤치마크 명령을 남겼다. 테스트는 기대하는 단순화와 기존 표현을 유지해야 하는 조건을 함께 고정한다.

읽을 때 확인할 점자료의 측정은 제시한 범위 검사 예제의 결과다. 다른 입력 분포나 전체 응용 프로그램의 이득을 보장하지 않는다.
