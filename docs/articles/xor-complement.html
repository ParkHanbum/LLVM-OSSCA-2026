상보적인 XOR 식을 상수로 접기

서로 반대인 비트 패턴을 찾아 AND는 0으로, OR는 모든 비트가 1인 값으로 바꾼다.

1. 이슈 선택

clang is suboptimal for (a ^ b) & (~a ^ b) where b is a specific constant 이슈: https://github.com/llvm/llvm-project/issues/75692 PR: https://github.com/llvm/llvm-project/pull/76637

  • good first issue
  • llvm:instcombine
  • missed-optimization

2. 패턴 해석

핵심 연산: (a ^ b) & (~a ^ b), b는 상수 (a ^ b) & ~(a ^ b) => x & ~x => 0

추가적으로 (a ^ b) | (~a ^ b), b는 상수 (a ^ b) | ~(a ^ b) => x | ~x => 0xFF = -1

7. 실제 patch 학습

코드 분석

// match(Op0, Pattern): Op0가 Pattern과 일치하는지 검사

// m_Xor(LHS, RHS): XOR 연산 패턴
// m_Xor(m_Value(A), m_APInt(C1)): xor <임의의 값 A>, <임의의 상수 C1> 패턴

// m_Value(A): 어떤 Value든 값을 A에 저장
// m_APInt(C1): 어떤 APInt 상수든 값을 C1에 저장
// m_Specific(A): 특정 Value A와 일치하는지 검사
// m_SpecificInt(~*C1): 특정 상수 ~*C1과 일치하는지 검사

// Constant::getNullValue(Op0->getType()): Op0의 타입에 대한 null 값 반환(0)
// Constant::getAllOnesValue(Op0->getType()): Op0의 타입에 대한 모든 비트가 1인 값 반환(-1)

if (match(Op0, m_Xor(m_Value(A), m_APInt(C1))) &&
    match(Op1, m_Xor(m_Specific(A), m_SpecificInt(~*C1))))
  return Constant::getNullValue(Op0->getType());

if (match(Op0, m_Xor(m_Value(A), m_APInt(C1))) &&
    match(Op1, m_Xor(m_Specific(A), m_SpecificInt(~*C1))))
  return Constant::getAllOnesValue(Op0->getType());

참고사항

InstructionSimplify는 대체 가능한지 검토하고 실제로는 InstSimplifyPass 에서 처리함.

InstructionSimplify.cpp
    │
    │ simplifyInstruction(&I, SQ)
    │
    └─ "I는 상수 0으로 대체할 수 있음"
       Value*로 i32 0 반환
                 │
                 ▼
InstSimplifyPass.cpp
    │
    ├─ I.replaceAllUsesWith(V)
    └─ 사용되지 않는 I 삭제

`m_Xor` vs `m_c_Xor`
m_c_Xor는 RHS, LHS에 대해서 교환 법칙을 적용해준다.
LLVM에서 교환 가능한 이항 연산에서 상수를 RHS로 두기 때문에 m_Xor 만으로도
- 불필요한 반대 순서 검사를 피하고
- A와 C1의 역할을 분명히 할 수 있다.

핵심 원리와 편집 주석

문제와 변환

대상은 (a ^ b) & (~a ^ b)이다. b는 정수 상수다. 두 피연산자는 비트 단위로 서로 반대다.

CPP
int src1(int a) { return (a ^ 4) & (~a ^ 4); }
int tgt1(int a) { return 0; }
int src2(int a) { return (a ^ 4) | (~a ^ 4); }
int tgt2(int a) { return -1; }

AND는 같은 위치의 두 비트가 모두 1일 때만 1이다. 상보적인 두 값에는 그런 위치가 없다. OR는 모든 위치에서 1이 된다.

구현 위치와 조건

InstructionSimplify.cpp의 AND·OR 단순화 경로가 이 패턴을 검사한다. 이 계층은 새 명령어 대신 기존 값이나 상수를 반환할 수 있다.

  • 같은 SSA 값 A를 사용하는 두 XOR인지 확인한다.
  • 두 상수가 같은 비트 폭에서 서로 보수인지 확인한다.
  • 결과 타입에 맞는 0 또는 all-ones 상수를 반환한다.

단순화 함수를 호출한 패스가 사용처를 바꾸고 불필요한 명령어를 제거한다. 상수를 오른쪽에 두는 LLVM의 정규 형태도 matcher 선택에 영향을 준다.

검증 기록

작성자는 C++에서 IR을 만들고 Alive2로 두 변환을 확인했다. 원자료에는 올바른 변환 2건과 오류 0건이 기록되어 있다.

기계어는 x86-64, AArch64, RISC-V 등으로 비교했다. RISC-V에서는 백엔드가 이미 같은 결합을 수행해 두 결과의 명령어 수가 같았다.

읽을 때 확인할 점원자료의 llvm-mca 수치는 O0 코드 블록의 정적 추정이다. 전체 프로그램의 실행 시간 개선을 뜻하지 않는다.

분석에서 확인한 점

IR에서 놓친 최적화가 최종 기계어에도 그대로 남는 것은 아니다. 백엔드가 같은 일을 하더라도 공통 IR을 일찍 정리하면 후속 패스가 더 단순한 입력을 받는다.

이 문서는 이미 존재하는 PR의 분석 기록이다. 연결된 PR을 작성자의 신규 제출 실적으로 해석하지 않는다.
