2. Existing fold

x & -x

x 10110000 -x 01010000 & 00010000
x & -x = x의 가장 낮은 set bit
  • 결과가 0이면 x == 0
  • 결과가 1이면 x의 최하위 비트가 1

패치 이전에 처리하던 비교

(x & -x) <s 0→x == INT_MIN
(x & -x) >s -1→x != INT_MIN

InstCombineCompares.cpp의 foldICmpAndConstant()에 있던 코드:

existing matchersigned comparison
// (X & -X) <  0 --> X == MinSignedC
// (X & -X) > -1 --> X != MinSignedC
if (match(And, m_c_And(m_Neg(m_Value(X)), m_Deferred(X)))) {
  Constant *MinSignedC = ...;
  return new ICmpInst(NewPred, X, MinSignedC);
}

x & -x matcher는 이미 있었지만, 결과를 0 또는 1과 비교하는 경우는 처리하지 않았다.

!= 1과 one-use

before1 instruction after producer
%r = icmp ne %lowbit, 1
after2 instructions
%lsb = trunc %x to i1
%r = xor i1 %lsb, true
and가 남는 경우 명령 수 증가. And->hasOneUse()일 때만 적용.

핵심 원리와 편집 주석

lowbit의 의미

x & -x는 x에서 가장 낮은 위치의 1비트만 남긴다. 비트 폭에 맞는 정수 연산을 전제로 다음 비교를 단순화할 수 있다.

원래 식단순화
(x & -x) == 0x == 0
(x & -x) != 0x != 0
(x & -x) == 1trunc x to i1
(x & -x) != 1not (trunc x to i1)

사용처와 비용 조건

0 비교와 1 비교는 새로 만드는 명령어 수가 다르다. != 1은 trunc와 NOT이 필요하므로 AND가 사라질 때만 적용하는 조건이 필요하다.

  • 비트 폭이 1보다 큰지 확인한다.
  • AND의 피연산자 순서를 바꾼 경우도 매칭한다.
  • 0·1 이외의 비교 상수는 이 규칙에서 처리하지 않는다.
  • != 1에는 AND의 one-use 조건을 적용한다.
  • neg가 다른 곳에서도 쓰이는 경우와 AND가 다른 곳에서도 쓰이는 경우를 구분한다.

구현과 리뷰

작성자는 초기 요청을 실제 이슈 #213708로 옮기고 PR #213709를 제출했다. 테스트를 먼저 추가한 커밋과 구현 커밋을 구분했다.

리뷰에서는 neg에 다른 사용처가 있는 테스트를 추가했다. 캡처하는 값이 lowbit 결과가 아니라 원래 X이므로 변수명도 MatchedX로 바꾸었다.

원자료는 focused 테스트, InstCombine 전체 테스트, CI 통과와 2026년 8월 9일 병합을 기록한다.

근거의 역할

스칼라와 vector, 비트 폭, 교환된 피연산자, 추가 사용처를 테스트했다. Alive2 링크도 제시했다.

읽을 때 확인할 점코퍼스와 backend 비용 자료에는 멘토가 제공한 근거가 포함된다. 이 문서는 그 자료를 멘티가 독립적으로 수집한 성과로 바꾸어 서술하지 않는다.
