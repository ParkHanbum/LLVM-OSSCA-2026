boolean sext와 곱셈을 select로 정규화하기

벡터의 x * (x == 0)을 직접 처리하는 대신 더 일반적인 곱셈 패턴을 단순한 선택으로 바꾼다.

01 · Issue

이슈와 문제 코드

대상 코드는 4개의 int lane을 가진 벡터에 x == 0 비교 mask를 곱한다.

C source 
typedef int V
    __attribute__((vector_size(4 * sizeof(int))));

V qux(V x) {
  return x * (x == 0);
}

비교 결과를 sign-extension한 mask는 각 lane에서 0 또는 -1이다. 핵심 IR과 기대 결과는 다음과 같다.

Before 
define <4 x i32> @src(
    <4 x i32> %x) {
  %cmp = icmp eq <4 x i32> %x,
                   zeroinitializer
  %mask = sext <4 x i1> %cmp
                   to <4 x i32>
  %r = mul <4 x i32> %x, %mask
  ret <4 x i32> %r
}
After 
define <4 x i32> @src(
    <4 x i32> %x) {
  ret <4 x i32> zeroinitializer
}

함수 속성과 데이터 레이아웃을 생략하고 SSA 이름을 정리했다.

02 · Semantics

sext i1과 곱셈의 의미

i1의 sign-extension은 원래 한 비트를 새 상위 비트에 복제한다. 따라서 false는 0, true는 all-ones인 -1이 된다.

조건 Xsext X(sext X) * Y같은 select
false00select X, -Y, 0
true-1-Yselect X, -Y, 0
mul (sext i1 X), Y ≡ select X, -Y, 0

원래 이슈 패턴

한 lane의 xx == 0 mask곱셈 결과
x == 0-10 * -1 = 0
x != 00x * 0 = 0

Alive2 검증

이슈와 PR에는 각각 원래 0 상수 변환과 일반 mul → select 변환의 Alive2 proof가 포함되어 있다.

Issue proof

x * (x == 0) → 0

03 · Root Cause

기존 코드가 놓친 이유

visitMul()에는 boolean extension과 곱셈을 다루는 인접 fold가 있었지만, sext i1과 variable Y의 곱셈은 처리하지 않았다.

처리하던 형태
mul Y, zext(i1 X)

select X, Y, 0으로 변환한다.

처리하던 형태
mul sext(i1 X), Constant

select X, -Constant, 0으로 변환한다.

빠져 있던 형태
mul sext(i1 X), Y

Y가 상수가 아닌 일반 값일 때 적용할 fold가 없었다.

원인 boolean sext의 값 범위는 0과 -1로 제한되지만, 기존 코드는 상수 곱셈에만 이 성질을 사용했다.

05 · Patch

추가된 일반 mul fold

// mul (sext X), Y -> select X, -Y, 0
// mul Y, (sext X) -> select X, -Y, 0
if (match(&I,
          m_c_Mul(m_OneUse(m_SExt(m_Value(X))),
                  m_Value(Y))) &&
    X->getType()->isIntOrIntVectorTy(1))
  return SelectInst::Create(
      X, Builder.CreateNeg(
             Y, "", /*HasNUW=*/false,

X = true: -1 * Y = -Y

06 · Pattern Match

matcher와 후속 fold

최종 구현은 곱셈의 교환법칙과 사용 횟수 조건을 matcher 안에 표현한다.

matcher역할
m_c_Mulsext가 어느 피연산자에 있어도 매치한다.
m_OneUsesext의 사용자가 현재 곱셈 하나인지 확인한다.
m_SExtsign-extension의 원본 값 X를 얻는다.
m_Value(Y)나머지 곱셈 피연산자를 Y로 잡는다.

원래 이슈가 0으로 접히는 경로

mul x, sext(x == 0)→select (x == 0), -x, 0→0
x == 0true 분기에서 -x = 0
x != 0false 분기에서 0

새 fold는 중간 select까지만 만든다. 최종 0 상수는 기존 InstCombine의 후속 단순화에서 얻어진다.

08 · Conclusion

결론

원인

variable과 곱하는 boolean sext 패턴이 visitMul()에 없었다.

구현

mul(sext X), Y를 select X, -Y, 0으로 정규화했다.

리뷰

이슈 전용 처리에서 scalar/vector와 피연산자 순서를 다루는 일반 fold로 변경됐다.

핵심 원리와 편집 주석

이슈의 식과 일반형

vector 비교 결과를 sext하면 각 원소는 0 또는 -1이다. x * sext(x == 0)은 x가 0인 경우와 그렇지 않은 경우에 모두 0이다.

TEXT
mul (sext i1 C), Y
        ↓
select C, -Y, 0

PR은 이슈의 전체 식을 직접 0으로 바꾸기보다 위 일반형을 추가했다. 원래 이슈는 새 select에 기존 단순화가 이어지며 0으로 접힌다.

타입·사용처·플래그

  • sext의 입력은 scalar i1 또는 vector i1이어야 한다.
  • sext가 현재 곱셈에서만 사용되는지 확인한다.
  • 곱셈의 두 피연산자 순서를 모두 처리한다.
  • 새 neg에는 기존 mul의 nsw를 전달한다.
  • nuw를 같은 방식으로 새 neg에 전달하지 않는다.

sext i2처럼 boolean이 아닌 입력은 같은 규칙으로 처리하지 않는다.

기존 코드와 리뷰의 역할

기존에는 zext boolean과 곱셈을 처리했다. sext boolean도 상수와 곱하는 경우는 처리했지만 일반 값 Y와의 조합이 빠져 있었다.

리뷰는 이슈 전용 처리에서 일반 fold로 범위를 바꾸었다. 곱셈 하나가 neg와 select로 바뀌는 비용 문제도 함께 논의했다.

검증과 읽을 때의 주의

자료는 원래 식의 상수 변환과 일반형 변환에 대한 Alive2 근거를 구분한다. scalar, vector, 플래그, 교환 순서, multi-use negative 테스트도 설명한다.

작성자의 로컬 재현에서는 scalar가 ret 0, vector가 ret zeroinitializer로 단순화되었다고 기록한다.

읽을 때 확인할 점이 문서는 기존 PR의 분석이다. 원자료의 이름 입력 자리표시는 확인된 자료 게시자 이름인 이하동으로 정리했다.
