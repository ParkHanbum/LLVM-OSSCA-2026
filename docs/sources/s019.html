문제의 값 흐름

비교 결과를 sext한 mask는 각 원소에서 0 또는 all-ones다. 같은 mask를 a와 b에 각각 AND한 뒤 더하는 것이 대상이다.

TEXT
mask = sext(condition)
(a & mask) + (b & mask)
             ↓
select condition, (a + b), 0

조건이 참이면 두 입력이 모두 남는다. 거짓이면 두 입력이 모두 0이 된다.

규칙이 있는데 적용되지 않은 이유

기존에는 and(sext C, V)를 select C, V, 0으로 바꾸는 규칙이 있었다. 그러나 sext가 한 번만 사용된다는 조건이 붙었다.

대상에서는 같은 mask가 두 AND에서 사용된다. 따라서 기존 규칙의 입력 조건을 통과하지 못했다.

새로운 전체 식 전용 규칙을 늘리는 방법과, 기존 정규화가 이어지도록 경계를 바꾸는 방법을 구분해 분석한다.

matcher와 후속 단순화

  • sext의 원본이 scalar 또는 vector i1인지 확인한다.
  • AND의 피연산자 순서를 모두 검사한다.
  • 공유된 mask와 각 사용처의 관계를 확인한다.
  • 생성한 select가 기존 덧셈 단순화로 이어지는지 확인한다.

원자료는 PR #81409와 코드 생성 결과를 연결한다. 한 번의 fold와 최종 출력 사이에는 기존 최적화가 여러 번 동작할 수 있다.

자료의 검증 결과

자료에는 Alive2 비교, llc 출력, regression test와 llvm-mca 결과가 포함되어 있다. 예제 블록에서 명령어 집계 500→400, Block RThroughput 1.3→1.0을 기록한다.

읽을 때 확인할 점위 값은 해당 블록과 모델의 결과다. 실제 프로그램의 실행 시간이나 모든 vector 입력의 개선율로 확대하지 않는다.
