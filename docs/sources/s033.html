대상 식

LLVM
; Before
%a = add nsw i8 %x, 1
%b = zext nneg i8 %a to i32
%r = add nsw i32 %b, -1

; After
%r = sext i8 %x to i32

zext의 입력이 음수가 아니면 같은 입력의 sext와 결과가 같다. 이 사실을 이용해 기존 sext 기반 fold를 재사용한다.

플래그와 기존 규칙

nneg는 단순한 힌트가 아니다. 전제를 위반한 입력은 poison이 될 수 있다. 내부 덧셈의 nsw와 확장 전후의 비트 폭도 변환 조건에 포함된다.

자료는 SExt만 찾던 matcher를 SExtLike로 넓히는 방향을 설명한다. 별도 식을 추가하기보다 같은 성질을 가진 입력을 기존 규칙에 연결한다.

문제의 출처와 학습 과정

원래 현상은 Rust의 match와 cast가 다른 IR로 내려가는 사례와 연결되어 있었다. 언어별 소스가 달라도 결함은 공통 LLVM 최적화에 있을 수 있다.

  1. Rust와 LLVM 이슈의 연결을 확인한다.
  2. 최소 src·tgt IR을 만든다.
  3. Alive2로 의미를 확인한다.
  4. Compiler Explorer에서 기계어를 비교한다.
  5. 기존 패치의 matcher와 테스트를 예상안과 대조한다.
